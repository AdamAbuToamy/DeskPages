DeskPages Privacy Notice
Version 0.8.36 alpha | Effective 22 October 2026
Developer: Adam Abu Toamy

DeskPages has no accounts, telemetry, analytics, advertising, or
code that uploads your desktop data to a server.

Update checks contact the official GitHub releases API after startup and every
six hours while the app is running. GitHub receives the connection IP address
and DeskPages version in the user agent, but no desktop files, screenshots or
page metadata. Turn automatic checks off in Check for updates. A manual check
is also available. Updates open the official release page and are installed
only when you choose; no downloaded code is run automatically. Version 0.8.16
and earlier need a one-time manual upgrade to receive this feature.

To organize the original Explorer desktop, it reads item identifiers, paths,
selection, icon positions, file attributes, sizes and modification times. It
changes managed items' visibility and stores page membership and layout metadata.
It does not need to read document contents to organize pages. System icons use
Windows desktop settings. Public Desktop items can require administrator access.

The app receives mouse/touchpad input and relevant shortcut key events to detect
navigation and context-menu creation positions. It does not record typed text.
Diagnostic logs can contain paths, item names, error messages, timing, counters
and system/version information. Diagnostic reports are only shared if you share
them yourself. Review/redact reports before attaching them to a public issue.

Animations capture the Explorer desktop, excluding ordinary application windows.
Direct mode uses transient graphics surfaces. Optional cached mode retains RAM
images and saves losslessly compressed, current-user DPAPI-encrypted desktop
snapshots under %LOCALAPPDATA%\DeskPages\HiddenPages\Snapshots. They can contain
your wallpaper, desktop icon names and positions. They are never uploaded.
Snapshots persist across normal restarts and are replaced after real changes.
Account/System directory permissions, exclusive live file locks and file
attributes resist ordinary opening and accidental deletion. The account owner
or administrator can deliberately bypass these controls; same-user DPAPI
secrecy and absolute deletion prevention are not promised. After stopping
DeskPages, you can clear the local snapshot folder; the app will rebuild it.

The settings memory indicator reads resident RAM counters for the agent and
matching helper programs in the current Windows session, plus total physical RAM.
It updates only while visible. These readings are not sent to a server.

Local settings, logs, journals, layout snapshots and restart checks are stored
under %LOCALAPPDATA%\DeskPages. Installation logs are also local. A user-requested
settings export includes page membership, file paths, icon positions and input
preferences, but not the files themselves. During edge dragging, a local helper
process uses a short-lived session folder under DeskPages\DragSessions to exchange
validated item paths, file identities and drop positions with the agent. It runs
with the normal Explorer user token and does not copy, move or delete user files.
Optional drag visual error logs may be retained locally for troubleshooting.
Session request/state files are removed on normal shutdown; interrupted sessions may remain. Keep exports private. They are not
content backups. Explorer/Windows/cloud sync services have their own behavior
and policies, including OneDrive if your Desktop is redirected there.

The installer creates startup tasks and uninstall entries and places program
files in your chosen protected folder. The program starts at sign-in. Windows
certificate or security checks can contact Microsoft or certificate authorities
independently of DeskPages.

Uninstallation attempts to restore file visibility and desktop layout. Local
recovery data is intentionally retained. Remove it only after stopping DeskPages
and verifying all files are visible and your layout is acceptable. Backups and
exports you created must be deleted separately if you no longer want them.

No cloud service, subscription, data sale or third-party analytics service is
operated by DeskPages. Future versions that change this behavior must update
this notice. No private support email address is configured for this preview.

Local recovery history stores page membership, icon coordinates, file identities
and preferences. Display profiles store display identifiers and geometry; the
Main display only option confines page layouts to the primary display. These
are metadata, not screenshots or document contents. Older organization metadata
is retained for compatibility even when its tools are absent from the daily UI.
Rescue operates independently of the main agent/input hooks/animation renderer.
For support, use Issues in the official AdamAbuToamy/DeskPages GitHub repository
once published. Private vulnerability reporting is enabled by the publishing
script; if unavailable, do not disclose private reports in public Issues.

Optional taskbar groups inspect only running windows and taskbar accessibility
metadata. They temporarily set per-window Shell grouping/relaunch properties;
no target app is launched or terminated. A local recovery journal under
DeskPages\TaskbarGroups stores HWND/process/start identities and original Shell
properties, which can include app identifiers, executable commands and icon paths.
A separate normal-user guardian restores those properties if the group helper
exits. Group membership is session-only; closing a window removes its membership.
The helper uses mouse-button state and pointer location for drag/drop, with no
keyboard text recording, screenshot capture or network requests. UI Automation
runs off the UI thread. The RAM indicator includes the helper and its guardian.

Classic process-only AppIDs may be resolved through a read-only mapping of installed Start menu/Desktop shortcut AppIDs to running executable paths. Shortcuts are not executed or modified.

While taskbar groups are enabled, a dedicated input thread inspects mouse button
presses and Escape to distinguish a numbered-target drop from native taskbar
reordering. It does not log typed text. Ordinary app clicks, app reordering and
group dragging remain native. Entry into a numbered group can complete the native
drag locally through tagged Windows SendInput events; leaving the target resumes
the same source from fresh hit regions. Dropping into a group has no hold timer
and never automatically opens a window picker. Unresolved or closed sources are
not assigned. An optional open-app picker is available only as an explicit menu
command. Copy taskbar diagnostics copies the most recent taskbar press decision,
button IDs, input flags and geometry to the local clipboard. All window resolution
and hit-region data remains on this computer.
